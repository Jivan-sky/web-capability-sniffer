# 分布式探索设计

## 适用场景

仅当用户要求分布式爬虫、子 Agent 探索或最小调度验证时使用。默认单浏览器、单会话探索即可。

## 任务拆分

**所有 worker 继承只读边界。** 子 Agent 不是“绕过限制的第二条通道”：不得执行 B/C 动作，不得重放请求，不得打开高危确认弹窗，不得使用高权限账号，不得做主动扫描/越权探测。无法证明 worker 只读，就不派发该任务。

按以下粒度拆分：

- 一级模块。
- 角色视角。
- 页面类型：列表、详情、配置、报表、工作台。
- Flow 类型：查询、只读详情、审核入口、配置入口、导出入口。

每个任务必须包含：

- 授权范围。
- 起始 URL 或导航路径（只走可见导航，不拼 URL 扫未链接路由）。
- 允许动作。
- 禁止动作。
- 产出 schema。
- 停止条件。
- 并发/频率/总时长预算。

## 登录态隔离

- 每个 worker 使用独立任务空间或浏览器上下文。
- 只复用用户已授权登录态，不复制或输出 Cookie、Token、鉴权头。
- 不跨租户、跨账号或跨域扩展。
- 不给 worker 比主会话更大的账号权限；无法证明权限不扩大，就不派发。

## 结果合并

按 `feature_id`、业务目标、页面入口、请求路径轮廓和 Flow 步骤合并。

冲突处理：

- 状态冲突时保留更保守状态。
- 证据等级冲突时保留来源和差异，不自动提升。
- 风险冲突时按最高风险处理。
- 重复 Flow 合并 Step，但保留所有入口证据。

## 失败恢复

- 单任务失败最多重试一次，且只允许重试 A 类只读导航；B/C 或未知副作用不重试。
- 同一外部障碍有两条独立失败证据后停止该分支。
- 失败结果也要写入 Evidence，来源类型为 `runtime_observed`，状态为 `不可用` 或 `阻断`。

## 最小调度验证

第一阶段只验证调度模型，不建设复杂平台：

- 至少拆出 2 个只读模块任务。
- 每个任务输出同一 schema 的小报告。
- 合并器生成去重后的 Feature / Flow / Evidence 摘要。
- 验证没有生产副作用、凭据泄露、越权尝试、主动扫描、请求重放、页面自动副作用和资源滥用。
