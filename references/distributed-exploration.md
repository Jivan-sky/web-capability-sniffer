# 分布式探索设计

## 适用场景

仅当用户要求分布式爬虫、子 Agent 探索或最小调度验证时使用。默认单浏览器、单会话探索即可。

## 任务拆分

按以下粒度拆分：

- 一级模块。
- 角色视角。
- 页面类型：列表、详情、配置、报表、工作台。
- Flow 类型：查询、只读详情、审核入口、配置入口、导出入口。

每个任务必须包含：

- 授权范围。
- 起始 URL 或导航路径。
- 允许动作。
- 禁止动作。
- 产出 schema。
- 停止条件。

## 登录态隔离

- 每个 worker 使用独立任务空间或浏览器上下文。
- 只复用用户已授权登录态，不复制或输出 Cookie、Token、鉴权头。
- 不跨租户、跨账号或跨域扩展。

## 结果合并

按 `feature_id`、业务目标、页面入口、请求路径轮廓和 Flow 步骤合并。

冲突处理：

- 状态冲突时保留更保守状态。
- 证据等级冲突时保留来源和差异，不自动提升。
- 风险冲突时按最高风险处理。
- 重复 Flow 合并 Step，但保留所有入口证据。

## 失败恢复

- 单任务失败最多重试一次。
- 同一外部障碍有两条独立失败证据后停止该分支。
- 失败结果也要写入 Evidence，来源类型为 `runtime_observed`，状态为 `不可用` 或 `阻断`。

## 最小调度验证

第一阶段只验证调度模型，不建设复杂平台：

- 至少拆出 2 个只读模块任务。
- 每个任务输出同一 schema 的小报告。
- 合并器生成去重后的 Feature / Flow / Evidence 摘要。
- 验证没有生产副作用、凭据泄露和越权尝试。
