# 只读执行规则：探索阶段永不写

> 本文件是 `web-capability-sniffer` 的硬边界。SKILL.md 的 Preflight 必须读它。
> 一句话：**授权只扩大「可记录范围」，不扩大「可执行范围」。**

**测试/沙盒也不例外**：本 skill 在任何环境都不执行写操作。测试环境写入另立受控流程（基线、快照/重置、回滚、审批、read-back），不在本 skill 内做。

## 一、三级动作策略

| 级别 | 定义 | 允许做什么 | 典型动作 |
|---|---|---|---|
| **A 只读观察** | 不改变服务器、账号、资金、外部可见状态，且副作用可预测 | 打开、滚动、展开、切换标签、翻页、排序、只读详情、合成条件查询、截图、记录网络轮廓 | 打开列表、按合成关键词查询、翻页、看详情 |
| **B 入口识别** | 有副作用或可能改变状态 | 只记录入口、按钮文案、路由、方法/路径、参数名、入口已可见的确认文案；**不点击、不提交、不打开高危确认弹窗、不执行** | 新增、编辑、保存、提交、发布、删除、导出、上传、审批、支付、改权限 |
| **C 绝对禁止** | 高风险、不可逆、批量或无法判断副作用 | **不尝试、不探测、不重放、不生成可执行脚本** | DDL/DML、批量删除、清空/重置/初始化、权限变更、资金、对外发送、生产配置修改、主动扫描/越权探测 |

判断顺序：**先按业务副作用判断，再按 HTTP 方法判断。** 只读查询即使是 POST 也可以观察；产生状态变化的 GET 也必须按 B/C 处理。

“可以观察”只指页面在正常 A 类操作中自己发出的请求；不得把请求复制出来重放。方法不是只读证明，业务副作用才是。

**A 类前置判断**：打开/刷新/展开/查询前，先排除自动保存、自动提交、异步任务、导出任务、消息发送、业务状态变化或明显资源消耗。排除不了 → 不做，按 C 处理。正常访问/操作审计留痕是预期结果，应记录，不按副作用处理。

## 二、浏览器动作规则

### 允许

- 打开页面、刷新、返回、滚动（刷新/展开前确认不会触发自动保存或自动提交）；
- 展开菜单、切换标签、打开只读详情（确认不会触发异步任务或副作用）；
- 翻页、排序、选择显示列但不保存；
- 使用合成/脱敏条件查询；
- 截图（能脱敏时）、语义快照、只读 DOM 检查；不导出 HAR、不保存完整请求/响应、不保存含个人信息的截图。

### 只识别，不点击

- 新增、编辑、保存、提交、发布、删除、作废、归档、停用、启用；
- 导出、下载业务数据、上传、导入；
- 发送消息、通知、邮件、短信、公告；
- 审批、通过、驳回、分配、转交、授权；
- 支付、退款、转账、充值、下单、发货；
- 修改配置、权限、角色、密码、密钥、版本、发布状态；
- 批量选择、批量处理、全选后操作；
- 任何带“生成/同步/初始化/重置/恢复默认/覆盖”的按钮。

### 绝对不点击

- 最终确认按钮（保存/提交/发布/删除/支付/审批/公开）；
- 确认弹窗里的“确定/确认/继续”；
- 任何出现“不可恢复/将影响生产/将通知外部/将扣费”提示的动作；
- 任何你无法判断副作用的按钮。

> 如果误开了确认弹窗：**按 Esc 或关闭，不点确定**；截图文案，记录为“已识别未执行”。

## 三、网络请求规则

1. **可以观察**页面自身发出的所有请求（方法、脱敏路径、参数名、响应字段轮廓）。
2. **禁止重放任何请求**：包括 `GET`/`HEAD`/`OPTIONS` 和所谓“只读 POST”；不得把浏览器请求复制到 curl/脚本/fetch。需要补证时，移交客户批准的只读验证流程。
3. **禁止**在浏览器控制台执行 SQL、调用写接口、修改全局对象、注入脚本改变页面行为。
4. **禁止**用“先请求一下看看”验证写接口；写接口只记录入口，不验证。
5. **禁止**绕过权限、验证码、风控、反爬；遇到即停。
6. **页面自动业务副作用也算写操作**：打开/刷新/展开后，若服务端自动创建/修改业务对象、发送外部消息、扣费或启动不可撤销的异步任务，立即停止后续加载，保留证据并按事故响应处理；不得以“页面自己发的”免责。**正常访问/操作审计日志是只读访问的预期留痕，应记录，不算业务写操作。**
7. **不打开高危确认弹窗**：删除/清空/重置/批量/权限/资金/对外发送的确认弹窗，一律不打开；即使客户/用户单独授权，也不在本 skill 内打开。只记录入口已经可见的文案。
8. **禁止主动安全测试**：端口扫描、目录/路由/账号枚举、字典爆破、注入探测、IDOR/越权验证、参数篡改、fuzz、DOM/JS 注入，一律禁止；需要做安全测试时另立授权、环境、工具链。
9. **禁止越权验证**：不改对象 ID、租户 ID、角色参数、用户 ID 去“看看能不能访问”；只记录入口与权限要求。
10. **禁止自动接受弹窗**：不自动点“确定/继续”，不自动提交表单，不关闭前端校验；确认弹窗只能按 Esc/关闭并记录文案。
11. **登录不等于写许可**：客户分配的授权账号内登录/建立会话允许，但只限登录本身；创建账号、改密码、改角色、改权限、共享账号、借用个人账号一律禁止。不得记录口令、验证码或 MFA 值；登录流程要求改密、绑定、授权或接受条款时停止并移交客户。
12. **禁止原始证据外带**：不导出 HAR、不保存完整请求/响应、不保存含 PII 的截图；网络证据只保留脱敏轮廓。
13. **控制资源消耗**：限制并发、频率、总时长；查询/分析/生成任务可能明显消耗资源时，先停并确认；不把生产系统当压测环境。

**报告声明要求**：报告必须写明“请求来源：页面自身触发；未复制、未重放、未导出 HAR、未保存完整请求/响应”。这是结构校验项，不是口号；缺声明即验收不通过。

## 三之一、运行时写保护（Preflight 必须启用）

文字规则挡不住误触，必须在浏览器层默认拒绝。详细接入见 [runtime-guard.md](runtime-guard.md)，参考实现见 `scripts/readonly_guard.js`。

| 控制 | 默认值 | 例外 |
|---|---|---|
| 非 `GET`/`HEAD`/`OPTIONS` | 一律阻断 | 无 |
| `POST` | 一律阻断 | 仅 owner 书面确认的专用只读查询端点，逐个加入 `allowReadPostPaths`；登录 POST 另用 `allowSessionPostPaths`；两者都只接受精确路径，禁止通配符/前缀 |
| 危险路径词（delete/drop/reset/grant/approve/pay/send/...） | 即使 `GET` 也阻断 | 无 |
| `confirm`/`alert`/`prompt` | 只 `dismiss`，绝不 `accept` | 无 |
| Guard 自身异常 | fail-closed，`abort` 并停止 | 无 |

规则：

1. **第一次导航前安装**；优先装在 BrowserContext，覆盖新标签页/弹窗。
2. 每次阻断都记 `C / 阻断 / 未触发 / 未知风险`，写原因；事件只保留脱敏 `origin + pathname`，不记录 query/body/header；然后停止该路径。
3. 临时放开某个非只读方法/路径 = 改变执行边界，必须停下重新取得授权；不得在运行中“先放开试试”。
4. 工具不支持请求拦截 → 用只读账号 + 人工观察 + 禁控制台/禁重放，并在报告写明“运行时写保护：未启用（原因/补偿控制/残余风险）”。
5. GraphQL 单端点即使加入只读白名单，也必须在 body 中拦截 `mutation`/`subscription`；路径放行不等于操作只读。

## 三之二、数据库与 SQL

本 skill **不连接数据库、不执行 SQL**。网页探查中发现的数据模型线索只记录在页面上可见的字段/枚举/状态机。

确需核对表结构时，另立“只读数据核对”任务，并同时满足：

1. 只读副本/只读账号；禁止生产写账号、管理员、共享账号；
2. 会话级只读：PostgreSQL `SET default_transaction_read_only = on`；MySQL `SET SESSION TRANSACTION READ ONLY`；
3. 只允许 `SELECT`/`SHOW`/`DESCRIBE`/`EXPLAIN`；禁止 DML/DDL/`GRANT`/`REVOKE`；
4. 设置语句超时与行数上限；
5. 只保留字段名、类型、枚举、状态机轮廓；不导出业务行数据。

没有只读通道 → 不做，记录盲区；不得用“我就看一眼”替代授权。

## 四、危险词与危险路由（命中即按 B/C 处理）

| 类别 | 词/模式（示例，不限于） |
|---|---|
| 删除/清空 | 删除、移除、清除、清空、作废、销毁、drop、truncate、delete、remove、clear、purge |
| 重置/初始化 | 重置、初始化、恢复默认、覆盖、回滚、reset、init、restore、overwrite、rollback |
| 发布/生效 | 发布、上线、启用、停用、提交、保存、生效、publish、deploy、enable、disable、submit、save |
| 权限/账号 | 授权、分配、转移、改密、绑定、解绑、角色、权限、grant、revoke、assign、role、permission |
| 对外/资金 | 发送、通知、公告、审批、通过、驳回、支付、退款、转账、充值、下单、send、notify、approve、pay、refund |
| 批量/导入 | 批量、全选、导入、同步、迁移、batch、bulk、import、sync、migrate |
| 导出/下载 | 导出、下载、另存、打印、export、download、saveas、print |
| 异步/计算 | 生成、分析、计算、刷新缓存、重建索引、跑批、generate、analyze、rebuild、refresh |
| 安全测试 | 扫描、探测、枚举、爆破、注入、越权、fuzz、scan、probe、enumerate、brute、inject、idor |

## 五、账号与凭据

- 优先使用**只读账号 / 最小权限账号 / 测试租户**；
- **硬门槛**：管理员账号、共享账号、生产负责人账号，或拥有超出探查范围写权限的账号 → 默认停止；优先换成只读账号。测试/沙盒环境如无只读账号，只能经客户书面例外并配置最小权限、审计和补偿控制后继续，且仍不得执行 B/C；生产环境没有只读账号 → 停止，书面例外也不适用。
- 不记录、不输出、不持久化密码、Token、Cookie、Authorization、会话 ID；
- 不在报告里写账号、客户、订单、联系方式、行级业务数据；
- 发现凭据泄露风险 → 立即停止该路径，记录为安全事件。

**生产环境唯一可接受路径**：真实只读账号或客户正式提供的只读角色。管理员、共享账号、生产负责人账号、拥有超出探查范围写权限的账号，即使客户给出书面例外，也不在本 skill 的生产探查中使用；转人工只读操作或另立安全测试授权。测试/沙盒环境可以申请最小权限账号，但仍不得执行 B/C 动作。

## 六、审计日志（每个动作都记）

报告中的审计表必须与 `report-template.md` / `validate_report.py` 的字段完全一致：

| 序号 | 时间 | URL/路径 | 动作 | 等级 | 执行状态 | 结果 | 请求来源 | 副作用判断 | 证据 ID |
|---|---|---|---|---|---|---|---|---|---|
| 1 | ISO 8601 + 时区 | 脱敏后的 origin + pathname | 打开/展开/查询/翻页/截图/识别入口 | A/B/C | 已执行（只读）/未执行/阻断 | 成功/失败/被阻断/未执行 | 页面自身触发/未触发 | 只读安全/只识别不执行/未知风险 | EVID-xxx |

选择器、确认弹窗、异常和停止原因写在“动作”或“结果”里，不得增加未定义的列；普通文本可选择器线索，不得含用户数据。

**逐动作审计是验收项**：报告必须附这张表的完整记录，每个打开/刷新/查询/展开/翻页/截图/入口识别一行；B/C 行的执行状态必须是“未执行”。只有汇总“写操作=0”而没有逐动作记录，视为不可验收。A 类动作可写“已执行（只读）”；任何 B/C 行动写“已执行”即验收失败。

## 七、可追溯 / 可回滚预判（每个 B/C 能力都要填）

| 问题 | 要拿到的证据 | 拿不到时 |
|---|---|---|
| 有没有审计日志？ | 谁/何时/什么对象/前后值/结果 | 标「未知」，默认不可写 |
| 能不能撤销？ | 撤销入口、软删除、版本历史、回收站、撤销窗口 | 标「未知」，默认不可写 |
| 有没有快照/备份？ | 备份对象、频率、保留期、恢复入口 | 标「未知」，默认不可写 |
| 恢复演练过吗？ | 最近一次恢复演练、RTO/RPO | 标「未演练」，不得称可回滚 |
| 外部副作用可逆吗？ | 消息/支付/审批/通知是否已发出、能否撤回 | 不可逆 → 只读或人工执行 |
| 权限能收回吗？ | 授权模型、回收路径、生效延迟 | 标「未知」，默认不可写 |

结论只能落五档：`只读安全` / `可写但需快照` / `可写但需审批` / `不可写` / `未知`。**未知按不可写处理。**

`未知风险` 不是“暂时当只读”的理由。证据补足前，它按写风险处理：不得标 `已验证 API`，CLI 适配只能是 `禁用占位`、`待受控交付` 或 `否`，Flow 不得标 `可重放`，Step 不得标 `只读安全`，且必须有一行可追溯/可回滚评估。

`未知风险` **不得给出任何可写结论**：`可写但需快照` / `可写但需审批` 也不行。必须先补证并重新分类为具体风险（数据导出/生产写入/对外发送/权限或配置变更），或保持 `未知`/`不可写`。否则会出现“不知道会写什么，却声称快照能覆盖”的假控制。

## 八、写操作移交（不在本 skill 内执行）

如果探查发现某个能力必须写：

1. 在报告里标 `写操作未执行` + `禁用占位/待受控交付`；
2. 记录入口、方法/路径、参数名、确认弹窗、权限要求、审计/回滚预判；
3. 明确移交到 FDE 的受控写入流程（`write-safety.md`）：基线快照、回滚对象、演练、dry-run、审批、幂等/限额/kill switch、read-back；
4. **不生成可直接执行的写脚本、不提供绕过审批的步骤、不把写接口标成“可封装 CLI”**。

## 九、事故响应

1. **立即停手**：停止当前路径，不再点、不再调、不再重试；
2. **保留现场**：截图、时间、URL、动作、请求、返回；不覆盖日志；
3. **通知 owner**：客户业务/IT/安全，按客户 incident 流程；
4. **先隔离，再恢复**：不要用“再写一次”掩盖；恢复前确认备份/快照可用；
5. **影子环境验证恢复**：能恢复并核对数据，再考虑生产；
6. **记录与复盘**：根因、影响范围、恢复步骤、证据、改进项；更新 deny-list。

> 误删表的教训：真正昂贵的不是删除动作，而是“删完继续点、继续试、继续补”导致现场被覆盖。第一动作永远是停手和保留证据。

## 十、自检

- 探索阶段写操作执行数 = 0？
- 所有 B/C 动作是否只识别、未执行？
- 每个 B/C 能力是否填了可追溯/可回滚矩阵？
- 未知项是否按「不可写」处理？
- 有没有记录凭据值、完整请求/响应、行级业务数据？
- 有没有生成可直接执行的写脚本？
- 有没有重放过任何请求，或把“页面自动发的”当免责理由？
- 第一次导航前装运行时 guard 了吗？阻断事件是否进了审计日志？
- 是否临时放开过非只读方法/路径？是否重新取得授权？
- 是否直连数据库或执行 SQL？只读事务/只读凭证/超时是否齐备？
- 有没有做主动扫描、越权探测、参数篡改、目录/账号枚举？
- 有没有导出 HAR、保存完整请求/响应或含 PII 截图？
- 账号是否为只读/最小权限；是否出现管理员、共享、生产负责人账号？
- 是否自动接受过确认弹窗或自动提交过表单？
- 是否限制并发/频率/总时长并对高资源动作先停？
- 出现确认弹窗/删除按钮/批量操作时，是否立即停止？
- 事故是否有停止、通知、证据、恢复、复盘？
