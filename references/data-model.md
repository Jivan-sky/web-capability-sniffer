# 探查数据模型

## 证据来源

- `user_confirmed`：业务 owner 或用户明确确认。
- `runtime_observed`：浏览器、网络事件、页面状态或命令实测。
- `repository_artifact`：代码、配置、测试、Skill 或 CLI 文件证明技术存在。
- `document_clue`：文档、历史笔记、旧方案，只作为线索。
- `hypothesis`：AI 根据上下文推断，必须待验证。

只有 `user_confirmed` 和 `runtime_observed` 可以直接支撑“已验证”结论。其他来源必须标记为线索或待确认。

## Feature

字段：

- `feature_id`：稳定 ID，如 `FEAT-001`。
- `模块`：一级导航或业务域。
- `页面/入口`：可见入口、URL 路径或导航路径，需脱敏。
- `功能名称`：面向业务用户的能力名。
- `角色线索`：当前登录角色、可见性或权限表现；未知写 `待确认`。
- `状态`：`已验证`、`页面已验证`、`仅入口`、`无法访问`、`未执行`、`仅推断`。
- `风险分类`：见 `boundaries.md`。
- `证据等级`：`高`、`中高`、`中`、`低`、`不可用`。
- `关联 flow_id`：无则写 `无`。
- `关联 evidence_id`：至少一个，无法取得时写盲区 ID。
- `人工审核建议`：`确认`、`合并`、`排除`、`补探`、`需 owner 定义`。

## Flow

字段：

- `flow_id`：稳定 ID，如 `FLOW-001`。
- `流程名称`：业务目标，不写成按钮名。
- `所属 feature_id`：可多个。
- `角色/前置条件`：登录态、页面位置、数据条件和权限要求。
- `触发入口`：导航路径或页面入口。
- `Step 列表`：按 `step_id` 顺序引用。
- `可重放状态`：`可重放`、`部分可重放`、`不可重放`、`未验证`。**只描述未来受控验证的可行性；本 skill 不执行重放，不能据此调用接口。**
- `验证状态`：`已验证`、`按需验证通过`、`待验证`、`阻断`。
- `输出用途`：`功能地图`、`操作手册`、`培训材料`、`API/CLI 候选`、`自动化候选`。

## Step

字段：

- `step_id`：稳定 ID，如 `STEP-001`。
- `flow_id`：所属流程。
- `动作类型`：打开、点击、展开、输入、查询、排序、翻页、读取、返回等。
- `目标/选择器线索`：语义定位优先；不要依赖易变行级文本。
- `输入数据策略`：无、合成、脱敏、用户提供；不得记录真实敏感值。
- `页面结果`：可见变化、空状态、错误提示或详情打开。
- `网络证据`：关联 `evidence_id`，无则写 `未取得`。
- `副作用判断`：只读安全、只识别不执行、未知风险。
- `可重放线索`：URL、语义定位、等待条件、断言轮廓。**只记录，不执行。**

## Evidence

字段：

- `evidence_id`：稳定 ID，如 `EVID-001`。
- `来源类型`：证据来源枚举。
- `采集方式`：语义快照、截图、CDP 请求、页面文本、权限错误、用户确认等。
- `触发 step_id`：无则写 `无`。
- `脱敏 URL/路径`：不得包含敏感查询值。
- `请求轮廓`：方法、路径、参数名、响应字段轮廓、错误轮廓。
- `页面轮廓`：标题、区域、控件、状态，不含行级业务值。
- `置信度`：高、中高、中、低、不可用。
- `限制/盲区`：未访问、未执行、权限不足、动态区域、无法脱敏等。

## 状态规则

- `已验证`：页面交互与结果已观察，且证据可复核。
- `页面已验证`：页面能力可见或可操作，但网络契约不足。
- `仅入口`：只看到菜单、按钮、标签、路由或静态线索。
- `无法访问`：权限、异常、验证码、风控、加载失败或账号范围阻断。
- `未执行`：因副作用或安全边界只识别入口。
- `仅推断`：来自命名、文档或静态线索，未运行观察。

未知字段统一写 `未取得`、`待确认` 或 `不适用`，不要留空。
