# 只读嗅探运行边界

> **本 skill 是只读探查 skill，不是变更执行 skill。** 探索阶段永不执行写操作；授权只扩大「可记录范围」，不扩大「可执行范围」。详细执行规则见 [read-only-enforcement.md](read-only-enforcement.md)。

## 核心原则

1. **探索阶段写操作执行数必须为 0。** UI、接口、SQL、脚本、CLI、浏览器控制台都算。
2. **授权不改变执行边界。** 客户/用户说“随便看”“有权限”只影响记录深度，不影响能否执行。
3. **不确定副作用 = 按最高风险处理，停止该路径。**
4. **写操作移交受控流程。** 本 skill 只输出入口、契约线索、风险与回滚预判，不生成写脚本。
5. **不做主动安全测试。** 端口扫描、目录/路由/账号枚举、爆破、注入探测、IDOR/越权验证、参数篡改、fuzz、DOM/JS 注入，一律禁止。
6. **只观察页面自身请求。** 不复制请求重放，不导出 HAR，不保存完整请求/响应或含 PII 截图。
7. **运行时默认拒绝。** 第一次导航前安装请求 guard，默认阻断非只读方法；`POST` 只有 owner 确认的只读端点才放行；弹窗只 dismiss。见 [runtime-guard.md](runtime-guard.md)。
8. **不直连数据库、不执行 SQL。** 确需核对表结构时另立只读数据核对任务，使用只读副本/只读凭证/只读事务/超时。

## 探测范围

- 外层边界是目标 URL 所属的同 origin URL 前缀。例如用户给 `https://app.example.com/home`，外层边界是 `https://app.example.com/`。
- 默认实际范围只覆盖目标页 + 从可见导航可达的同 origin 页面/模块；不拼 URL 扫未链接路由，不做目录/路由枚举。
- 不跨 origin 扩展，不跨租户，不进入外链支付页、第三方控制台或无关后台模块。
- 超出已确认范围时停止，并记录为“可见但未探测”。

## 自动允许（A 类）

- 打开、读取、刷新、返回、滚动（刷新/展开前确认不会触发自动保存或自动提交）。
- 展开菜单、切换标签、打开只读详情（确认不会触发异步任务或副作用）。
- 翻页、排序、选择显示列但不保存配置。
- 在页面中用合成、脱敏或用户明确提供的条件触发只读筛选和查询。
- 观察页面状态和网络请求结构。

> 以上仅限可预测为只读的动作。若打开/刷新/展开后页面自动创建/修改业务对象、发送外部消息、扣费或启动不可撤销的异步任务，立即停止后续加载，保留证据并按事故响应处理；不得以“页面自己发的”免责。正常访问/操作审计日志是预期留痕，应记录，不算业务写操作。

## 入口识别（B 类，只识别不执行）

- 导出、下载业务数据、上传文件。
- 新增、编辑、保存、提交、发布、归档、停用。
- 发送消息、通知、邮件或短信。
- 删除、作废、关闭、批量处理。
- 分配、转交、审批、授权、修改配置。
- 购买、支付、退款或其他资金动作。
- 全量/批量导出、下载业务数据、上传文件、导入/同步/迁移。
- 任何会产生生产业务数据变化、外部通知、资金变化或明显资源消耗的动作；正常访问审计留痕不在此列。

以上动作：**只记录入口、按钮文案、路由、方法/路径、参数名、确认弹窗文案；不点击、不提交、不执行。**

## 绝对禁止（C 类）

- 绕过登录、权限、验证码、风控或反爬。
- 猜测、抓取、输出或持久化密码、Token、Cookie、鉴权头和会话信息。
- 批量抓取与目标无关的数据。
- 为验证功能而修改生产数据。
- 把低置信线索写成已验证事实。
- 把网页中发现的业务能力继续生成 CLI、Skill 或 Plugin。
- DDL/DML、清空/重置/初始化、权限变更、资金、对外发送、生产配置修改。
- 从浏览器复制任何请求并用 curl/脚本/fetch 重放，包括 GET/HEAD/OPTIONS 和所谓只读 POST。
- 直连数据库执行 DDL/DML、`GRANT`/`REVOKE`，或用管理员/共享/生产写账号“看一眼”。
- 在运行时临时放开非只读方法/路径后继续，不重新取得授权。
- 端口扫描、目录/路由/账号枚举、字典爆破、注入探测、IDOR/越权验证、参数篡改、fuzz、DOM/JS 注入。
- 自动接受 confirm/alert、自动确认、自动提交、关闭前端校验。
- 导出 HAR、保存完整请求/响应、保存含个人信息的截图。

## 运行前权限边界确认

运行 skill 前必须先完成权限边界确认。不要先打开浏览器、等待用户登录、采集网络请求，再回头询问。

如果用户本轮没有完整说明以下信息，先用一个合并问题询问，不得开始探查：

- 目标 URL、系统边界和是否按同前缀探查。
- 登录方式和账号性质：只读账号、测试账号、沙箱环境，还是其他。**管理员、共享、生产负责人或超大权限账号默认停止；生产环境只接受真实只读账号/客户正式只读角色，即使有书面例外也不使用管理员/共享/生产负责人账号；没有只读账号就停止。**
- 目标交付：功能地图、只读 CLI 契约、操作手册、自动化候选等。
- **允许记录的操作类别**：只读；创建/写入；修改/保存；上传；下载/导出；删除；对外发送/公开；资金交易；凭据、账号或权限配置；明显消耗资源的任务。
- **禁止记录/禁止触碰的类别**：哪些类别或页面绝对不能碰；是否禁止打开最终确认弹窗。
- **最终确认边界**：是否允许在入口已经可见时记录“生成/提交/保存/删除/支付/公开”的文案；确认弹窗一律不打开、不点击，即使客户单独授权也不在本 skill 内打开。

如果用户说“完全权限”但没有给出账号性质、操作类别或最终确认边界，仍需追问这些边界。运行前问题不得预设尚未探查到的站内功能名；只能询问通用操作类别。得到完整确认后，先复述记录范围，再开始只读探查。

数据、预算、停止条件和失败处理不是固定前置问题。运行中遇到某个具体动作，且缺少测试数据、费用/调用约束或处理口径时，再向用户补问。

询问模板：

```text
在运行网页嗅探前，我需要先确认本次权限边界：
1. 目标范围：外层按你给的 URL 所属同 origin 前缀；默认实际只探查目标页和可见导航可达的页面/模块，不拼 URL 扫未链接路由。例如 `https://app.example.com/home` 的外层边界是 `https://app.example.com/`。是否有需要排除的路径或跨域入口？
2. 账号性质：这是只读账号、测试/沙箱账号，还是其他账号？生产探查只接受真实只读账号或客户正式只读角色；管理员、共享或生产负责人账号即使有书面例外也不用于生产探查。
3. 交付目标：只读功能地图、只读 CLI 契约，还是操作手册/自动化候选？
4. 允许记录的操作类别：只读之外，是否需要记录创建/写入、修改/保存、上传、下载/导出、删除、对外发送/公开、资金交易、凭据/账号/权限配置、明显消耗资源的任务的入口？
5. 禁止记录/禁止触碰的类别：哪些类别或页面绝对不能碰？默认禁止打开最终确认弹窗；如有例外，请按动作单独说明。
6. 最终确认边界：是否允许在入口可见时记录“生成/提交/保存/删除/支付/公开”的文案？本 skill 不打开高危确认弹窗、不点击最终确认。

说明：本 skill 只读探查，不会执行上述写操作；授权只影响记录深度，不影响执行边界。在你确认前，我只会做只读浏览和入口识别。
```

## 授权只扩大记录范围

- 用户授权某类动作，意味着：**可以记录它的入口、契约线索、风险、回滚预判**；
- 不意味着：可以点击、提交、调用、重放、生成可执行脚本；
- 写操作需要另行走 FDE 的受控写入流程（基线快照、回滚演练、dry-run、审批、幂等/限额/kill switch、read-back）。

## 数据最小化

- 仅保留完成能力判断所需的最少信息。
- 不保存或输出 Cookie、Token、请求头、账号、客户、订单、手机号、邮箱、完整请求体、完整响应体或行级业务数据。
- 网络证据只保留方法、脱敏路径、参数名/类型/必填性、分页/排序/筛选字段名、响应字段轮廓、错误轮廓、权限表现和状态。
- 截图无法安全脱敏时不要保存或交付。
- 不导出 HAR；HAR 含请求头、Cookie 和完整载荷，不属于可交付证据。

## 逐动作审计日志

探索期间每个打开/刷新/查询/展开/翻页/截图/入口识别都要记一行：时间、脱敏 URL、动作、A/B/C 级别、执行状态、结果、请求来源、副作用判断、证据 ID。报告必须附这张表；B/C 行的执行状态必须是“未执行”。只有汇总“写操作=0”而没有逐动作记录，视为不可验收。

结论不是“我真的没写”，而是“每个动作都能被审计，且所有 B/C 动作都停在入口识别”。两者缺一不可。

## 判断原则

- 按业务副作用判断，不按 HTTP 方法判断。
- 只读查询即使使用 POST 也可以观察；产生数据变更的 GET 也不得执行。
- “观察”只指页面正常 A 类操作产生的请求；不得复制出来重放，也不得手工构造请求补证。
- 无法确定副作用时按高风险处理并停止。

## 可追溯 / 可回滚评估

每个 B/C 能力和每个 `未知风险` 能力必须记录：审计日志、撤销/软删除、快照/备份、恢复演练、外部副作用可逆性、权限回收。结论只能落五档：`只读安全` / `可写但需快照` / `可写但需审批` / `不可写` / `未知`。未知按不可写处理；`未知风险` 不得标 `已验证 API`，CLI 适配只能是 `禁用占位`、`待受控交付` 或 `否`，且**不得给出任何可写结论**（`可写但需快照`/`可写但需审批` 也不行）——必须先补证并重新分类为具体风险，或保持 `未知`/`不可写`。

## 写操作移交

发现写能力时：

1. 标 `写操作未执行` + `禁用占位/待受控交付`；
2. 记录入口、方法/路径、参数名、确认弹窗、权限要求、审计/回滚预判；
3. 移交 FDE 的 `write-safety.md`（基线快照、故障域隔离、回滚演练、dry-run、审批、幂等/限额/已演练的 kill switch、read-back、台账 fail-closed）；
4. 不生成可直接执行的写脚本，不提供绕过审批的步骤，不把写接口标成“可封装 CLI”。

## 事故响应

停手 → 保留现场 → 通知 owner → 隔离/恢复 → 影子环境验证 → 记录复盘。不要用“再写一次”掩盖第一次的错误。

## CLI-ready 输出边界

- 输出后续 CLI 设计所需的命令树、接口契约和差距清单，不生成、修改、测试、安装或发布 CLI，除非用户另行提出实现任务。
- 页面可见、菜单可见、路由存在或静态代码线索，不等于接口已验证。
- 导出、下载、生产写入、对外发送、权限/配置变更一律只能作为 `禁用占位` 或 `待受控交付`；`未知风险` 只能作为 `禁用占位`、`待受控交付` 或 `否`。即使发现接口、即使客户授权，也不得在本 skill 内执行验证。
- 缺少参数、响应、错误或权限证据时，明确写“未取得/待确认”，不得根据命名猜测。
