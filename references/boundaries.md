# 只读嗅探运行边界

## 探测范围

- 默认覆盖目标 URL 所属的同 origin URL 前缀。例如用户给 `https://foxapi.cn/home`，默认可探测 `https://foxapi.cn/` 前缀下的页面、路由和接口。
- 不跨 origin 扩展，不跨租户，不进入外链支付页、第三方控制台或无关后台模块。
- 超出已确认范围时停止，并记录为“可见但未探测”。

## 自动允许

- 打开、读取、刷新、返回、滚动。
- 展开菜单、切换标签、打开只读详情。
- 翻页、排序、选择显示列但不保存配置。
- 使用合成、脱敏或用户明确提供的条件执行只读筛选和查询。
- 观察页面状态和网络请求结构。

## 运行前权限边界确认

运行 skill 前必须先完成权限边界确认。不要先打开浏览器、等待用户登录、采集网络请求，再回头询问副作用范围。

如果用户本轮没有完整说明以下信息，先用一个合并问题询问，不得开始探查：

- 目标 URL、系统边界和是否按同前缀探查。
- 登录方式和账号性质：测试账号、沙箱环境或用户明确承担副作用的真实账号。
- 目标交付：功能地图、只读 CLI、可执行副作用 CLI、操作手册、自动化候选等。
- 允许操作类别：只读；创建/写入；修改/保存；上传；下载/导出；删除；对外发送/公开；资金交易；凭据、账号或权限配置；明显消耗资源的任务。
- 禁止操作类别：必须明确不能触碰的动作类别、页面范围和最终确认按钮。
- 最终确认：是否允许点击“生成/提交/保存/删除/支付/公开”等最终确认按钮。

如果用户说“完全权限”但没有给出账号性质、允许操作类别或最终确认边界，仍需追问这些边界。运行前问题不得预设尚未探查到的站内功能名；只能询问通用操作类别。得到完整确认后，先复述执行范围，再开始探查。

数据、预算、停止条件和失败处理不是固定前置问题。运行中遇到某个已授权操作类别下的具体动作，且缺少测试数据、费用/调用约束或处理口径时，再向用户补问。

询问模板：

```text
在运行网页嗅探前，我需要先确认本次权限边界：
1. 目标范围：默认按你给的 URL 所属同前缀探查；例如 `https://foxapi.cn/home` 会覆盖 `https://foxapi.cn/` 前缀下页面、路由和接口。是否有需要排除的路径或跨域入口？
2. 账号性质：这是测试/沙箱账号，还是你愿意承担副作用的真实账号？
3. 交付目标：只读功能地图、只读 CLI 契约，还是允许补齐可执行副作用 CLI 的契约？
4. 允许的操作类别：只读之外，是否允许创建/写入、修改/保存、上传、下载/导出、删除、对外发送/公开、资金交易、凭据/账号/权限配置、明显消耗资源的任务？
5. 禁止的操作类别：哪些类别或页面绝对不能触碰？是否禁止点击最终确认按钮？

在你确认前，我只会做只读浏览和入口识别。
```

## 副作用授权门槛

写入、生成、上传、删除、导出、发送、充值、支付、审批、权限配置等动作默认不得执行。只有用户明确确认以下信息后才可在范围内执行：

- 账号性质：测试账号、沙箱环境或用户明确承担副作用的真实账号。
- 允许动作：具体到生成、上传、删除、导出、保存、公开、充值等动作类型。
- 最终确认：是否允许点击最终确认按钮；未明确时只能打开前置页面或确认弹窗，不能点最终确认。

缺任一项时，先向用户合并询问授权范围；在确认前只识别入口和只读网络线索。执行具体动作时，如果需要测试数据、文件、费用/调用上限或异常处理口径，再即时向用户补问。

## 只识别、不执行

- 导出、下载业务数据、上传文件。
- 新增、编辑、保存、提交、发布。
- 发送消息、通知、邮件或短信。
- 删除、作废、关闭、批量处理。
- 分配、转交、审批、授权、修改配置。
- 购买、支付、退款或其他资金动作。
- 任何会产生生产数据变化、外部通知、审计事件或明显资源消耗的动作。

上述动作在用户明确授权后不再属于“只识别、不执行”，但必须严格限制在授权范围内，并记录预期副作用、实际结果和清理建议。

## 绝对禁止

- 绕过登录、权限、验证码、风控或反爬。
- 猜测、抓取、输出或持久化密码、Token、Cookie、鉴权头和会话信息。
- 批量抓取与目标无关的数据。
- 为验证功能而修改生产数据。
- 把低置信线索写成已验证事实。
- 把网页中发现的业务能力继续生成 CLI、Skill 或 Plugin。

## 数据最小化

- 仅保留完成能力判断所需的最少信息。
- 不保存或输出 Cookie、Token、请求头、账号、客户、订单、手机号、邮箱、完整请求体、完整响应体或行级业务数据。
- 网络证据只保留方法、脱敏路径、参数名/类型/必填性、分页/排序/筛选字段名、响应字段轮廓、错误轮廓、权限表现和状态。
- 截图无法安全脱敏时不要保存或交付。

## 判断原则

- 按业务副作用判断，不按 HTTP 方法判断。
- 只读查询即使使用 POST 也可以观察；产生数据变更的 GET 也不得执行。
- 无法确定副作用时按高风险处理并停止。

## CLI-ready 输出边界

- 输出后续 CLI 设计所需的命令树、接口契约和差距清单，不生成、修改、测试、安装或发布 CLI，除非用户另行提出实现任务。
- 页面可见、菜单可见、路由存在或静态代码线索，不等于接口已验证。
- 导出、下载、生产写入、对外发送、权限/配置变更在未授权时只能作为禁用占位或待授权验证；即使发现接口也不得执行验证。
- 缺少参数、响应、错误或权限证据时，明确写“未取得/待确认”，不得根据命名猜测。
