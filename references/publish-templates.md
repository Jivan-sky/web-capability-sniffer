# 发布物模板

## 动作审计日志

每个打开/刷新/查询/展开/翻页/截图/入口识别一行；字段：序号、时间、URL/路径、动作、等级（A/B/C）、执行状态、结果、请求来源、副作用判断、证据 ID。B/C 行执行状态必须为“未执行”；报告没有这张表，验收不通过。

## 功能地图

字段：

- `feature_id`
- `模块`
- `页面/入口`
- `功能名称`
- `角色线索`
- `状态`
- `风险分类`
- `证据等级`
- `关联 flow_id`
- `关联 evidence_id`
- `人工审核建议`

## Flow 清单

字段：

- `flow_id`
- `流程名称`
- `所属 feature_id`
- `角色/前置条件`
- `触发入口`
- `Step 列表`
- `可重放状态`
- `验证状态`
- `输出用途`

## Step 证据表

字段：

- `step_id`
- `flow_id`
- `动作类型`
- `目标/选择器线索`
- `输入数据策略`
- `页面结果`
- `网络证据`
- `副作用判断`
- `可重放线索`

## Evidence 索引

字段：

- `evidence_id`
- `来源类型`
- `采集方式`
- `触发 step_id`
- `脱敏 URL/路径`
- `请求轮廓`
- `页面轮廓`
- `置信度`
- `限制/盲区`

## 可追溯 / 可回滚评估

每个写风险 `feature_id` 一行，字段：

- `feature_id`
- `能力/动作`
- `副作用`
- `审计日志`
- `撤销/软删除`
- `快照/备份`
- `恢复演练`
- `外部副作用可逆性`
- `权限回收`
- `可写性结论`

`feature_id` 必须与功能地图一致；`可写性结论` 只能取 `只读安全` / `可写但需快照` / `可写但需审批` / `不可写` / `未知`。写风险能力和 `未知风险` 能力都不能写 `只读安全`，未知按不可写处理。

## 操作手册草稿

按角色和 Flow 输出：

1. 适用角色和使用场景。
2. 前置条件。
3. 操作步骤。
4. 成功结果。
5. 常见异常。
6. 注意事项。

不要包含真实客户、订单、账号、手机号、邮箱、Token、Cookie 或行级业务数据。

## 培训材料草稿

按业务场景输出：

- 场景目标。
- 相关模块。
- 推荐流程。
- 关键判断点。
- 常见误区。
- 需人工确认事项。

## API/CLI/Agent Skill 候选

仅从已验证网络证据生成候选：

- `候选 ID`
- `来源 feature_id/flow_id`
- `候选类型`：API、CLI、Agent Skill、自动化脚本。
- `业务价值`
- `只读边界`
- `所需证据`
- `当前状态`：可设计、草案、待验证、禁用、不建议。
- `缺口`

报告还必须声明：`请求来源：页面自身触发；未复制、未重放、未导出 HAR、未保存完整请求/响应。`

CLI-ready 的详细字段继续使用 `cli-readiness.md`。
