# 探查工作流

## Preflight

先做运行前权限边界确认，再开始任何浏览器或网络探查。若本轮用户没有明确目标 URL、账号性质、目标交付、允许记录的操作类别、禁止记录/禁止触碰的类别和最终确认边界，先询问并等待回复。生产环境只接受真实只读账号/客户正式只读角色；管理员/共享/生产负责人账号即使有书面例外也不使用。

运行前问题不得预设目标站具备哪些功能。**只读 CLI 也只从页面自身产生的只读请求中提取契约，不直接调用或重放接口**；涉及创建/写入、修改/保存、上传、下载/导出、删除、对外发送/公开、资金交易、凭据/账号/权限配置或明显资源消耗的动作，**只识别入口，不执行**；即使客户/用户授权，也不在本 skill 内执行，也不重放任何请求。

外层边界按用户给定 URL 的同 origin 前缀；默认实际只探查目标页和从可见导航可达的页面/模块，不拼 URL 扫未链接路由。例如 `https://app.example.com/home` 的外层边界是 `https://app.example.com/`。跨 origin、跨租户和第三方入口另行授权。

**运行时 guard 是 Preflight 的一部分**：第一次导航前安装默认拒绝的请求拦截（见 [runtime-guard.md](runtime-guard.md)）；`allowReadPostPaths` 与 `allowSessionPostPaths` 默认都为空，除非每个精确路径都有 owner 确认；登录不得混入只读查询白名单。弹窗只 dismiss。工具不支持拦截时，先记录补偿控制（只读账号 + 人工观察 + 禁控制台/禁重放）。本 skill 不直连数据库、不执行 SQL；需要数据层核对时另立只读任务。

## Scope

记录目标、时间、登录态、角色线索、系统边界、默认深度和安全策略。没有明确授权时只探查目标页和同域直接入口。记录“探索阶段写操作执行=0”和“授权不改变执行边界”。

同时记录逐动作审计日志：每个打开/刷新/查询/展开/翻页/截图/入口识别一行；B/C 行执行状态必须是“未执行”。没有这张表，报告不可验收。

运行时 guard 的每次阻断也记一行：等级 `C`、执行状态 `阻断`、请求来源 `未触发`、副作用判断 `未知风险`，并写阻断原因。阻断后停止该路径，不换方法重试。

## Map

1. 打开默认落地页并记录标题、URL 轮廓、可见区域和加载异常。
2. 识别一级导航、顶部入口、全局按钮、搜索、筛选、列表、详情、表单、弹窗、iframe 和画布。
3. 每个入口先创建 `Feature`，即使只看到入口也保留状态。
4. 将一级导航、顶部入口、全局能力和二级菜单分开统计，不要混加。

## Explore

允许自动执行（A 类）：

- 打开、刷新、返回、滚动（刷新/展开前确认不会触发自动保存或自动提交）。
- 展开菜单、切换标签、打开只读详情（确认不会触发异步任务或副作用）。
- 翻页、排序、选择显示列但不保存配置。
- 在页面中用合成、脱敏或用户明确提供的条件触发只读筛选和查询。

只识别不执行（B 类）：

- 导出、下载、上传。
- 新增、编辑、保存、提交、发布、归档、停用。
- 发送消息、通知、邮件或短信。
- 删除、作废、关闭、批量处理。
- 分配、转交、审批、授权、配置修改。
- 购买、支付、退款或其他资金动作。

绝对禁止（C 类）：

- DDL/DML、清空/重置/初始化、批量导入、权限变更。
- 从浏览器复制任何请求并用 curl/脚本/fetch 重放，包括 GET/HEAD/OPTIONS 和所谓“只读 POST”。
- 在控制台执行 SQL、调用写接口、修改全局对象。
- 绕过权限、验证码、风控、反爬。
- 端口扫描、目录/路由/账号枚举、字典爆破、注入探测、IDOR/越权验证、参数篡改、fuzz、DOM/JS 注入。
- 自动接受 confirm/alert、自动确认、自动提交、关闭前端校验。
- 导出 HAR、保存完整请求/响应或含个人信息的截图。

测试/沙盒也不写；本 skill 在任何环境都不执行 B/C 动作。测试环境写入另立受控流程。

**出现确认弹窗：按 Esc/关闭，不点确定；截图文案，记录“已识别未执行”。高危确认弹窗一律不打开。**

**页面自动业务副作用：** 打开/刷新/展开页面后，若服务端自动创建/修改业务对象、发送外部消息、扣费或启动不可撤销的异步任务，立即停止后续加载，保留证据并按事故响应处理；不得用“页面自己发的”免责。正常访问/操作审计日志是预期留痕，应记录，不算业务写操作。

**资源消耗：** 限制并发、频率、总时长；查询/分析/生成任务可能造成明显资源消耗时，先停并确认，不把生产系统当压测环境。

## 可追溯 / 可回滚预判

对每个 B/C 能力记录：

| 问题 | 证据 | 结论 |
|---|---|---|
| 有没有审计日志（谁/何时/什么对象/前后值/结果）？ | 未取得（无证据按不可写） | 有/无/未知（未知按不可写） |
| 能不能撤销（撤销入口/软删除/版本历史/回收站）？ | 未取得（无证据按不可写） | 有/无/未知（未知按不可写） |
| 有没有快照/备份（对象/频率/保留/恢复入口）？ | 未取得（无证据按不可写） | 有/无/未知（未知按不可写） |
| 恢复演练过吗（最近一次/RTO/RPO）？ | 未取得（无证据按不可写） | 已演练/未演练/未知 |
| 外部副作用可逆吗（消息/支付/审批/通知）？ | 未取得（无证据按不可写） | 可逆/不可逆/未知 |
| 权限能收回吗（模型/回收路径/生效延迟）？ | 未取得（无证据按不可写） | 能/不能/未知 |

结论：`只读安全` / `可写但需快照` / `可写但需审批` / `不可写` / `未知`。**未知按不可写处理。**

## Capture

- 每个业务目标形成一个 `Flow`，每个页面动作形成一个 `Step`。
- 捕获动作前后的语义快照、可见结果、错误提示和新增网络请求。
- 截图仅用于布局、画布、虚拟列表等语义快照不足的场景；无法脱敏时不要保存。
- 网络记录只保留契约轮廓，不保留值。
- 每个 Step 标 `执行状态=已执行/未执行/被阻断`；B/C 动作一律 `未执行`。
- 禁止重放任何请求；只观察页面自身产生的请求。需要补证时移交客户批准的只读验证流程。
- 不导出 HAR；不保存完整请求/响应或含 PII 截图。

## Normalize

- 合并同义功能，保留所有入口证据。
- 将功能归入模块、角色、页面、业务流程和发布用途。
- 将重复请求合并为请求契约索引。
- 对无法复核的条目标记为 `仅推断` 或 `待确认`。

## Flow 验证

第一阶段只对少量核心 Flow 做按需验证：

- 优先选择只读、安全、业务价值高、步骤短的 Flow。
- 验证最小可重放线索：入口、动作、等待条件、断言轮廓、预期结果。
- 不建设完整自动化测试体系，不做定时或 CI 执行。
- 若使用 Playwright/浏览器自动化，只能执行 A 类只读导航和取证；不得用脚本重放 B/C 动作，不得打开高危确认弹窗。

## Publish

同一份 Flow 可以生成：

- 功能地图：模块、功能、角色、状态、证据等级。
- 操作手册：按角色和流程生成步骤说明（只写只读/人工确认后动作）。
- 培训材料：按业务场景组织关键流程、注意事项和常见错误。
- API/CLI 候选：仅从已验证网络证据中提炼；写接口只做禁用占位/待受控交付。
- 自动化候选：只读、稳定、可复核的关键 Flow；只输出线索，不执行重放。

报告必须包含：探索阶段写操作执行=0、写操作执行清单=无、授权不改变执行边界=否、每个 B/C 能力的可追溯/可回滚评估、未执行动作、盲区、停止原因。
